# LSP Tools 实现计划

## 目标

在 nanocode 中加入只读 LSP tools，让 agent 可以通过 language server 查询代码结构和符号位置，用于更快、更准地规划和实现代码变更。

第一版目标是可控的 MVP：提供稳定的只读查询能力，不做编辑、重命名、code action、formatting，也不把 LSP 作为必需依赖。

## 设计原则

- LSP tool 是只读工具，`EFFECT = READONLY`。
- LSP tool 应加入 `TOOL_REGISTRY` 和 `PLAN_MODE_TOOLS`，plan mode 可以用它做探索。
- LSP server 进程是运行期临时资源，不写入 conversation，也不放进可持久化状态。
- 先支持最有价值、协议相对直接的 request，再扩展 diagnostics/completion。
- LSP 失败必须降级成普通 tool failure，不影响其他工具和 agent loop。

## 第一版范围

支持子命令：

- `Lsp(symbols, path)`
  - 优先用 `textDocument/documentSymbol`。
  - 输出文件内符号树或扁平符号列表，包含 name/kind/range/selectionRange。
- `Lsp(definition, path, line, column)`
  - 调 `textDocument/definition`。
  - 输出目标 uri/range。
- `Lsp(references, path, line, column)`
  - 调 `textDocument/references`，默认 `includeDeclaration=true`。
  - 输出引用位置列表。
- `Lsp(hover, path, line, column)`
  - 调 `textDocument/hover`。
  - 输出 hover 文本和 range。

暂缓：

- `diagnostics`
  - 依赖 `textDocument/didOpen`、`publishDiagnostics`、server 初始化时机和缓存策略，复杂度更高。
- `completion`
  - 输出体积大、上下文敏感，先不做。
- rename/codeAction/formatting/applyEdit
  - 会产生写操作，不属于只读 MVP。

## 配置

在 config 中加入 LSP 配置，建议结构：

```toml
[lsp.python]
extensions = [".py"]
language_id = "python"
command = ["pyright-langserver", "--stdio"]

[lsp.typescript]
extensions = [".ts", ".tsx", ".js", ".jsx"]
language_id = "typescript"
command = ["typescript-language-server", "--stdio"]
```

Runtime 配置：

```toml
[runtime]
lsp_timeout = 10
```

解析为：

- `Config.lsp_servers: dict[str, LspServerConfig]`
- `LspServerConfig.name`
- `LspServerConfig.extensions`
- `LspServerConfig.language_id`
- `LspServerConfig.command`
- `RuntimeSettings.lsp_timeout`

匹配规则：

1. 根据文件扩展名找 server config。
2. 找不到时返回清晰错误：`no LSP server configured for extension .py`。
3. command 找不到或启动失败时返回清晰 tool failure。

## 状态和生命周期

新增临时运行期组件：

- `LspManager`
  - 持有 `dict[str, LspServerSession]`。
  - key 建议用 `(server_name, workspace_root)`。
  - 负责获取/创建 session。
  - 提供 `shutdown_all()`。
  - 提供只读状态接口 `status_summary()`，不得触发 server 启动或探测。
- `LspServerSession`
  - 管理 `subprocess.Popen`。
  - 管理 request id。
  - 负责 `initialize`、`initialized`、request、shutdown/exit。
  - 负责 stdout JSON-RPC 读写和 stderr drain。
  - 记录轻量状态：server name、language id、workspace root、initialized/idle/busy/crashed、最近错误。

状态放置建议：

- `AgentRuntime.lsp_manager: LspManager | None`
- 不放 `RuntimeState`，因为 `Popen` 和协议 session 不是可持久化会话状态。

清理位置：

- `AgentLoop` 退出时调用 `agent.shutdown()` 或类似方法。
- `Agent.cancel_current_goal()` 不应关闭 LSP server，避免用户继续任务时重复冷启动。
- 进程 crash 后，下次 request 应丢弃旧 session 并重建。

状态展示：

- Status bar 只显示 active LSP session 数量，例如 `lsp:2`。
  - 没有 active session 时不显示。
  - 不显示 server 名字，避免状态栏过长。
  - 不为了展示状态启动 server。
- `/status` 显示已启动 session 详情，例如：
  - `lsp: pyright(on), rust-analyzer(idle)`
  - crashed session 显示 `name(crashed)`，可附最近错误摘要。
- `/config` 显示已配置 server 名称，例如：
  - `lsp.servers: python, typescript`
  - 未配置时显示 `(empty)`。

建议接口：

```python
@dataclass(frozen=True)
class LspStatusItem:
    name: str
    language_id: str
    state: str
    workspace: str
    last_error: str = ""

class LspManager:
    def status_summary(self) -> tuple[int, list[LspStatusItem]]:
        ...
```

调用规则：

- Status bar 只读 `count`。
- `/status` 使用 `items` 格式化详情。
- `/config` 只读 `Config.lsp_servers`，不访问 manager。

## 协议细节

必须实现：

- JSON-RPC framing:
  - 写：`Content-Length: <bytes>\r\n\r\n<body>`
  - 读：解析 header，读取指定字节 body。
- request id:
  - 单调递增 int。
  - response id 必须匹配。
- initialize:
  - `processId`
  - `rootUri`
  - `capabilities`
  - `workspaceFolders` 可选。
- initialized notification。
- request timeout:
  - 使用 `runtime.lsp_timeout`。
  - 超时后返回 tool failure，必要时 kill session。
- shutdown:
  - request `shutdown`
  - notification `exit`
  - 超时则 kill。
- stderr drain:
  - 后台线程读取 stderr，保留最近 N 行用于错误信息。

文件 URI:

- path 统一通过 `session.resolve_path()`。
- path 必须在 cwd 内。
- 转换为 `file://` URI。
- line/column 使用 LSP 的 0-based position。

文档同步：

- 第一版可以在每次 request 前发送 `textDocument/didOpen`，内容来自磁盘当前文件。
- version 可简单递增或固定为 1。
- 后续可优化成 didChange 缓存。

## Tool 接口

新增：

```python
class LspTool(Tool):
    NAME = "Lsp"
    EFFECT = ToolEffect.READONLY
    SIGNATURE = "Lsp(command, path[, line, column]) -> LspToolResult<content>"
```

参数：

- `symbols`: `["symbols", "path"]`
- `definition`: `["definition", "path", "line", "column"]`
- `references`: `["references", "path", "line", "column"]`
- `hover`: `["hover", "path", "line", "column"]`

输出：

- 使用 `<LspToolResult>` tag。
- 包含 `command`, `path`, `language_id`, `server`, `status`。
- 位置用 `path:start_line:start_col-end_line:end_col`。
- 大结果依赖现有 tool result bound/log 机制。

## 实现步骤

1. 添加 `LspServerConfig` 和 config 解析。
2. 添加 `RuntimeSettings.lsp_timeout` 和默认 config。
3. 添加 `LspServerSession`，用 fake server 测试 framing、initialize、request、shutdown。
4. 添加 `LspManager`，负责 session 缓存、重建和关闭。
5. 在 `AgentRuntime` 上挂 `lsp_manager`，在 agent/loop 退出时清理。
6. 添加 `LspTool`，实现参数解析和四个 MVP 子命令。
7. 注册 `LspTool` 到 `TOOL_REGISTRY` 和 `PLAN_MODE_TOOLS`。
8. 更新 status bar、`/status`、`/config` 的 LSP 展示，不触发 server 启动。
9. 补 README/help/tool description。
10. 跑语法检查、相关测试、全量测试。

## 测试计划

新增 `tests/test_nanocode_lsp_tool.py`。

重点测试：

- config 解析：
  - extension -> server config。
  - 缺失配置返回清晰错误。
- JSON-RPC framing：
  - request 写入包含正确 `Content-Length`。
  - response id 匹配。
  - malformed response 失败可读。
- fake LSP server：
  - initialize/initialized 顺序。
  - documentSymbol。
  - definition。
  - references。
  - hover。
- tool 参数：
  - 缺参数、非整数 line/column、未知 command。
  - path outside cwd。
- plan mode：
  - `Lsp` 在 plan mode 允许执行。
  - `Edit/Bash/mutating Git` 仍被阻止。
- cleanup：
  - manager shutdown 会发送 shutdown/exit。
  - timeout 会终止坏 session。
- 状态展示：
  - status bar 无 active session 时不显示 `lsp`。
  - status bar 有 active session 时只显示数量。
  - `/status` 显示 session 名称和 state。
  - `/config` 显示配置的 LSP server 名称。
  - 读取 status/config 不启动 LSP server。

验证命令：

```sh
python3 -m py_compile nanocode.py
uv run pytest tests/test_nanocode_lsp_tool.py -q
uv run pytest -q
uv run ruff check .
```

## 风险和取舍

- LSP 生命周期复杂。第一版只做 request/response 和 didOpen，避免 diagnostics/completion。
- 不同 server 对 capabilities 和方法支持不一致。tool 输出需要显示 `method not supported`，而不是静默失败。
- 长驻 server 可能泄漏。必须有 shutdown_all 和 crash/timeout cleanup。
- 真实 server 测试不稳定。单元测试使用 fake server，真实 pyright/rust-analyzer 只作为手动验证。
- line/column 0-based 可能让用户困惑。tool description 必须明确，输出也应清晰。
- LSP 返回结果可能很大。依赖现有 tool result bound/log，不在 LspTool 内另做复杂截断。

## 后续扩展

- diagnostics:
  - didOpen 后等待 publishDiagnostics。
  - 支持缓存最近 diagnostics。
- completion:
  - 增加结果数量限制。
  - 输出 label/kind/detail/documentation excerpt。
- workspace/symbol:
  - `Lsp(workspace_symbols, query)`。
- prepareRename/rename:
  - 只在后续显式设计写工具时考虑，不混入只读 `LspTool`。
